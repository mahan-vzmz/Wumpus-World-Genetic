# ۲. معماری سیستم

## اجزای اصلی

| فایل | مسئولیت |
|---|---|
| `map_parser.py` | خواندن و اعتبارسنجی سخت‌گیرانه فایل نقشه |
| `environment.py` | قوانین بازی، امتیاز، پایان و ادراک‌ها |
| `base_agent.py` | رابط مشترک عامل‌ها |
| `astar_agent.py` | برنامه‌ریزی A-Star با اطلاعات کامل |
| `knowledge_base.py` | حافظه و استنتاج محلی |
| `rule_based_agent.py` | تصمیم‌گیری قاعده‌محور و backtracking |
| `genetic_agent.py` | استخراج ویژگی و سیاست وزن‌دار ترکیبی |
| `genetic_algorithm.py` | Fitness، انتخاب، crossover، mutation و elitism |
| `map_generator.py` | تولید قطعی نقشه‌های آموزش و تست |
| `experiment.py` | اجرای benchmark، خلاصه، CSV و نمودار |
| `docs/build_artifacts.py` | ساخت قابل‌بازتولید گزارش PDF و ارائه |

## جریان اجرای یک اپیزود

1. نقشه توسط parser اعتبارسنجی می‌شود.
2. محیط و عامل ساخته می‌شوند.
3. `reset()` دقیقاً یک بار برنامه یا حافظه عامل را آماده می‌کند.
4. عامل فقط observation مجاز را دریافت می‌کند.
5. محیط اکشن را اجرا و state، reward، done و info را برمی‌گرداند.
6. پایان طبیعی، خطای عامل یا `max_steps` با علت مشخص ثبت می‌شود.
7. خروجی استاندارد برای benchmark تولید می‌شود.

## تصمیم‌های طراحی نسخه 8

- برنامه‌ریزی A-Star دیگر در constructor و reset دوبار اجرا نمی‌شود.
- نبود فایل وزن ژنتیکی خطای واضح ایجاد می‌کند.
- خانه چاهی که عامل وارد آن شده، دیگر به اشتباه safe تلقی نمی‌شود.
- parser خطوط اضافی، خروج ناامن، شروع ناامن و نقشه بدون طلا را رد می‌کند.
